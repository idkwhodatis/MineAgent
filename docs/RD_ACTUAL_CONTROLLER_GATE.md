# Actual maintained RD controller gate

This successor composes the pinned installed FactorCoSTEER loop with a real
host-ticket/SO_PEERCRED controller, retained fixture-model request/response ledger,
source parser/publication, protected numeric candidate, native HDF publication,
fresh normalizer primitive report, complete single-day execution snapshot, and
measured feedback/adoption. It does not register the public RD dispatcher or
permit arbitrary generated programs. The only executable source in this gate is
byte-exact `runtimes/factor_execution/abi_fixture.py` returned by the fixture model.

The declared output window is 2024-03-15 inclusive to 2024-03-16 exclusive; the
candidate receives two prior sessions plus the current session. One cutoff is the
entire declared window, not a partial-window success. The three output values are
compared with the independently specified maintained momentum oracle. No paid
provider or general alpha-quality claim is involved.

`tests/integration/rd_controller_fixture.py::run_actual_generation` creates a real
owned synthetic dataset and retained canonical input bytes, genuine RD run/spec/
attempt/budget, then invokes the controller. No source or process receipt fixture
stands in for execution. The dedicated workflow requires its exact named case,
with no skip accepted, builds all three immutable images, and reproduces the
installed controller wheels. Local collection is not execution evidence.

## Host observation and termination

Non-root host readers cannot dereference `/proc/PID/ns/pid` for the protected
nondumpable leader/child. The new read-only, exact-container Docker observer uses
the same daemon-side `docker top -eo pid,uid,ppid,pidns,comm` mechanism already
exercised by the hostile deadline proof. It preserves the existing real namespace
inode identity; it does not substitute a guessed value or treat NSpid as inode
identity. Strict bounded output is cross-checked with before/after host stat,
status, cgroup and exact container/image/running leader inspection. Every event
checks the authenticated socket and fresh pair; the database resolver independently
binds the observer's container/image/leader to retained launch receipts. No Docker
exec, capability addition, dumpability change or privileged host helper is used.

Historical `stop.v1` receipts continue to prove positive absence only. They do not
claim an exit cause. Successful worker completion additionally requires actual
Docker ExitCode 124, OOMKilled false, observed kernel exit at the original deadline
(with the existing one-second observation allowance), complete child quiescence
reports, and an accepted generation. The actual measured exit code is retained in
the existing attempt field. Early exit/OOM still permits containment recording but
cannot produce successful worker completion. No actual result is fabricated when
create/start/stop has an uncertain outcome.

## Remaining acceptance obligations

The default entry point remains closed. This implementation is not accepted until
its exact composed head passes the actual PostgreSQL plus Docker gate and stopped
controller cold backup/restore. General unknown launch resolution, lost final-ACK
recovery, cancellation/resume, multi-generation execution, full general window
iteration, and public worker/API/UI integration are not claimed by this slice.
A pending snapshot publication can be retried through its immutable idempotent
publisher without another numeric unit; partial execution before publication
still requires explicit reconciliation and is never silently relaunched.

The required controller workflow now contains three exact, non-skippable cases:
actual single-day generation, a second real generation followed by cold
backup/restore, and a lost identity-callback containment case. The latter seeds only a real synthetic user, retains the actual
fixture dataset bytes, requires every process stopped, compares all four semantic
closures and every retained file after restoration, and never treats restored
rows as live launch authority. PostgreSQL clients stream through the unchanged
exact-container CI adapter; private archives and raw test diagnostics are not
uploaded. These are authored gates, not a claim that PostgreSQL/Docker acceptance
has run locally.


## Containment recovery successor

`recover_controller_unit` reads the exact retained launch, image/config/CID and
kernel identities, removes only that unit, and requires both Docker name/CID
absence plus old leader/known child absence before a stop receipt. It never
recreates a unit, imports output, grants controller access or refunds a budget.
An unobserved created/exited container may be physically removed only after full
configuration/CID validation; its missing kernel identity remains uncertain and
no synthetic PID or stop receipt is manufactured. Inputs and reservations remain
held for investigation. A true running identity may be observed and retained
before containment, independently of the expired execution deadline.

Stale-lease recording is limited to the old admission's immutable real receipts
and stopped state under owner/run/attempt locks. It cannot mutate a newer attempt,
settle budget or publish source/evaluation results. A still-current worker can
separately charge its full conservative reservation and mark its own failure.
The new real callback-loss case must execute actual Docker and PostgreSQL, retain
physical stop despite the failed callback, and prove no source was published.
The 30-second recovery observer/kernel-wait budget is not a total wall-time claim;
each bounded Docker command independently has its existing ten-second ceiling.
