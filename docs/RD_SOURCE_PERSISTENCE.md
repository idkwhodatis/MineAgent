# RD source persistence boundary (revision 018)

This revision follows `017_numeric_process_boundary`. It is a source-storage and
semantic-closure prerequisite, **not RD-Agent engine acceptance**. Default submit,
API dispatch, RD controller issuer/launcher, provider registration and production
execution remain closed. Existing legacy run DTOs and historical validator
functions retain their old meaning.

The new internal path retains actual bounded model request/response files and
physical-call ledger rows, re-reads response bytes with the pinned JSON parser,
binds ordered continuation parts, publishes the exact selected source through a
fenced, flush-only FactorVersion transaction, and records a bounded read witness.
Source is retained even when invalid Python; this boundary never executes it.
Reservations are arbitrated by one immediate cross-family consumer ledger;
legacy factor admission also counts pending source byte/file peaks.

A genuine RD run has no fake legacy strategy. Its exact frozen configuration,
dataset, versioned broker protocol, context and budget must agree in both services
and deferred SQL. Run-scoped NOWAIT locks serialize direct SQL graph mutation.
Only initial generation and fresh attempt binding are enabled. Final evaluation,
adoption, checkpoint and generic candidate-input publication tables remain closed.
The numeric maintained-fixture issuer separately persists real pre-evaluation and
cutoff lineage and exact admitted input inventory; it cannot claim general PIT
materialization or successful evaluation.

The internal fixture `tests/integration/rd_source_fixture.py` accepts exact source
bytes, RuntimePins and budget. It uses real files/transactions/ledger/parser/source
publication. Its RD controller is an explicitly **admitted, unexecuted precursor**,
not authenticated IPC or a stopped process. Actual numeric images may be supplied
by the composed PG + Docker test; placeholder default image pins are storage-only.

`rd_source_closure` uses `mineagent.rd-source-restore-closure.v1`; shared research
closure v4 adds the explicit operation protocol. Earlier closure grammars remain
unchanged. RD closure validation re-reads retained files and permits quiescent
unpublished records without inventing successful outcomes. Whole backup continues
to reject an active/admitted controller. Component source closure tests are not
stopped-controller cold-restore evidence. That obligation belongs to the subsequent
actual controller → candidate → native HDF → fresh normalizer loop.

The static Alembic SQL is generated by `script/generate_rd_source_migration.py`.
Empty downgrade refuses all RD evidence, removes only revision-owned objects with
RESTRICT, and preserves legacy/numeric evidence. Historical anonymous CHECK
expressions are restored; PostgreSQL-generated constraint names are not claimed
byte-identical. No files are deleted by migration.

Local validation has no PostgreSQL or Docker daemon. Real PG source, direct-SQL,
canonical JSON, identity and backup tests are collected here but require hosted
execution before this migration is accepted. Local tests and collection are not a
substitute for that gate. The operational controller and end-to-end loop remain
the next required implementation, followed by worker/API/UI integration.
